## 오늘의 핵심: `useSeen()`이 대체 뭔가

3단계에서 직접 만들어 놓고도 "이게 무슨 함수지?"가 남아 있었음. 정리하면:

**`useSeen()` = "본 물고기 서랍"을 여는 열쇠.** 어제(07-23) 내가 `context/seen.tsx`에 직접 만든 커스텀 훅이다.

```
const { isSeen } = useSeen();
       ↑              ↑
   필요한 것만      서랍 열기
    꺼내 쓰기
```

서랍 안에 든 세 가지 (`SeenContextValue` 타입에 적어둔 그대로):

| 이름 | 정체 |
|---|---|
| `seenIds` | 본 어류 id 배열 — `['1', '5', '7']` |
| `isSeen(id)` | 봤는지 묻는 함수 → `true` / `false` |
| `toggleSeen(id)` | 봤다/안 봤다 뒤집기 |

**필요한 것만 골라 꺼낸다**(구조 분해)는 게 포인트:

- 도감 목록 → "봤어?"만 물어보면 되니까 `isSeen` 하나
- 상세 화면 → 버튼도 눌러야 하니까 `isSeen, toggleSeen` 둘

### 왜 Context가 필요한가 (props 넘기기의 고통)

Context가 없으면 데이터를 손에서 손으로 넘겨야 한다. 중간에 있는 컴포넌트는 자기가 쓰지도 않는 데이터를 받아서 넘겨주기만 함:

```
앱 → 탭들 → 도감 화면 → 카드 한 줄   😩
```

Context는 중간을 건너뛴다:

```
     ┌─── 서랍(SeenProvider) ───┐
     │                          │
  도감 화면              상세 화면
  useSeen()              useSeen()
```

→ `app/_layout.tsx`에서 앱 전체를 `SeenProvider`로 감싼 이유가 이것. **서랍이 모두의 머리 위에 있어야 아무 화면에서나 열 수 있다.**

### `use`로 시작하는 이름의 의미

`use`로 시작하는 함수 = **훅(Hook)**. React의 약속이고, 규칙이 하나 붙는다:

> 컴포넌트 **맨 위에서**, **조건문 없이** 호출해야 한다.

- 그래서 `useSeen()`을 `if` 안이나 `renderItem` 안에 넣으면 안 되고, 28번 줄(컴포넌트 시작 직후)에 둔 게 맞다
- 이름을 `use`로 시작하면 ESLint가 이 규칙을 대신 검사해준다

## 배운 것 (한 줄 정리)

- **커스텀 훅은 내가 만드는 것이다.** `useState`처럼 React가 준 것만 훅인 게 아니라, `useSeen`/`useFavorites`처럼 직접 만들어 쓴다
- **같은 패턴을 세 번째 쓰면 설명이 필요 없어진다.** ⭐ 줄을 보고 👀 줄을 유추할 수 있었던 게 그 증거
- **모르는 코드가 나오면 그게 내가 쓴 코드일 수도 있다.** 정의 파일(`context/seen.tsx`)을 열어보는 게 첫 번째 수순
